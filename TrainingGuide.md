# SSAMem Training Guide

This guide describes the recommended workflow for building a PopQA latent
experience bank with a pointer table:

```text
PopQA task input
-> collect-text-mas-trajectories
-> build-ssa-data
-> train-ssa
-> build-experience-bank
-> evaluate/query MemoryAgent
```

The important idea is that the memory we want to store is a past MAS
trajectory, not a plain QA context. Therefore, the training data for
`train-ssa` should come from collected MAS trajectories.

## 1. Two Separate Data Flows

There are two related but different flows:

```text
Training flow:
text MAS trajectories -> SSA manifest/latents -> trained composer/projector

Experience-bank flow:
SSA manifest/latents + trained checkpoint -> latent memory bank + pointer table
```

`train-ssa` does not directly consume the raw PopQA file. It consumes an SSA
manifest generated by `build-ssa-data`.

## 2. Prepare PopQA Task Input

Prepare a JSONL file where each row has at least:

```json
{
  "task_prompt": "What is George Rankin's occupation?",
  "target_text": "politician",
  "context_text": "Known answer aliases: [\"politician\"]"
}
```

Example path:

```text
data/trajectories/popqa_input.jsonl
```

If you already have a trajectory-context dataset such as:

```text
data/trajectory_context_popqa2500_qwen3_4b_768/all/manifest.jsonl
```

then the collection/build steps may already have been completed.

## 3. Collect Text MAS Trajectories

This is the teacher-side data collection step. A text-only MAS answers each
PopQA task and saves its role-by-role trajectory.

```bash
python -m ssamem collect-text-mas-trajectories \
  --input data/trajectories/popqa_input.jsonl \
  --output data/trajectories/popqa_text_mas.jsonl \
  --runtime-mode hf \
  --model-name-or-path Qwen/Qwen3-4B-Instruct-2507 \
  --trust-remote-code \
  --device cuda \
  --torch-dtype float16 \
  --load-in-4bit \
  --limit 2500 \
  --task-domain popqa \
  --mas-style camel \
  --max-new-tokens 192
```

Output:

```text
data/trajectories/popqa_text_mas.jsonl
```

This file is the raw trajectory source for SSA training data.

## 4. Build SSA Data From MAS Trajectories

Convert the collected trajectories into an SSA manifest and latent tensor
shards. This is the step that prepares the actual input for `train-ssa`.

```bash
python -m ssamem build-ssa-data \
  --input data/trajectories/popqa_text_mas.jsonl \
  --output data/trajectory_context_popqa2500_qwen3_4b_768/all \
  --runtime-mode hf \
  --model-name-or-path Qwen/Qwen3-4B-Instruct-2507 \
  --trust-remote-code \
  --device cuda \
  --torch-dtype float16 \
  --load-in-4bit \
  --latent-max-tokens 768
```

Main output:

```text
data/trajectory_context_popqa2500_qwen3_4b_768/all/manifest.jsonl
data/trajectory_context_popqa2500_qwen3_4b_768/all/latents/*.pt
```

If you need train/validation folds, split the generated manifest into paths
such as:

```text
data/trajectory_context_popqa2500_qwen3_4b_768/folds/fold_00/train.jsonl
data/trajectory_context_popqa2500_qwen3_4b_768/folds/fold_00/val.jsonl
```

Use the train manifest for `train-ssa` and the val manifest for probing or MAS
evaluation.

## 5. Train SSA Composer/Projector

`train-ssa` trains the composer/projector so that latent trajectory memories can
be injected into the MAS agent.

Recommended config:

```text
configs/ssamem_phaseA_trajectory_context_popqa2500_768_b4_answerstrong.yaml
```

Run:

```bash
python -m ssamem train-ssa \
  --config configs/ssamem_phaseA_trajectory_context_popqa2500_768_b4_answerstrong.yaml \
  --device cuda \
  --run-name phaseA-popqa-trajectory
```

The config should point to the trajectory-derived SSA manifest:

```yaml
data:
  manifest: data/trajectory_context_popqa2500_qwen3_4b_768/all/manifest.jsonl
  valid_manifest: data/trajectory_context_popqa2500_qwen3_4b_768/folds/fold_00/val.jsonl
```

The current `train-ssa` command trains from `data.manifest`. The
`valid_manifest` field is useful for follow-up probing/evaluation commands.

Output checkpoint example:

```text
outputs/phaseA_popqa2500_768_b4_answerstrong/fold_00/distiller.pt
```

## 6. Build Latent Experience Bank and Pointer Table

Use the trained checkpoint to project each trajectory latent into an injectable
memory and register it into the MemoryAgent.

Recommended k-means pointer-cluster build:

```bash
python -m ssamem build-experience-bank \
  --config configs/ssamem_phaseA_trajectory_context_popqa2500_768_b4_answerstrong.yaml \
  --manifest data/trajectory_context_popqa2500_qwen3_4b_768/all/manifest.jsonl \
  --checkpoint outputs/phaseA_popqa2500_768_b4_answerstrong/fold_00/distiller.pt \
  --device cuda \
  --limit 1000 \
  --cluster-method offline-kmeans \
  --kmeans-clusters 50 \
  --kmeans-max-iter 50 \
  --output-path outputs/experience_bank/popqa_bank1000_kmeans50.json
```

This produces a report containing:

```text
pointer table rows
pointer -> cluster
cluster -> indexed latent memories
```

Note: the JSON report is not yet a full persistent database snapshot. It is a
record of the runtime-built bank. If you need reusable on-disk memory storage,
use or extend the persistence path through `kernel.storage_root`.

## 7. Evaluate the Full MemoryAgent Loop

Run the full MAS + MemoryAgent SEARCH + latent injection loop:

```bash
python -m ssamem eval-mas-memory-agent-loop \
  --config configs/ssamem_phaseA_trajectory_context_popqa2500_768_b4_answerstrong.yaml \
  --bank-manifest data/trajectory_context_popqa2500_qwen3_4b_768/all/manifest.jsonl \
  --eval-manifest data/trajectory_context_popqa2500_qwen3_4b_768/folds/fold_00/val.jsonl \
  --checkpoint outputs/phaseA_popqa2500_768_b4_answerstrong/fold_00/distiller.pt \
  --device cuda \
  --bank-limit 1000 \
  --limit 20 \
  --top-k 3 \
  --cluster-method offline-kmeans \
  --kmeans-clusters 50 \
  --kmeans-max-iter 50 \
  --memory-request-policy require-search \
  --max-new-tokens 64 \
  --output-path outputs/mas_latent_eval/memory_agent_loop_fold00_bank1000_kmeans50.json
```
